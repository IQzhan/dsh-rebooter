# 状态面板 — 设计说明

本文是 **DSH Server** 状态面板的规范原文英文版见 [`status-panel.md`](status-panel.md)。

## 要解决什么

不打开 DSH 聊天界面，也能看见启动 / 关闭 / 重启 / 更新 / 打开界面的进度；一个桌面入口 **DSH Server**；关掉或最小化面板**绝不**影响 DSH 与监督进程。

## 明确不做（已丢弃）

- 五个独立桌面启动器 → 改由一个面板聚合。
- 空闲时也常驻整页控制台 → 只在任务进行中（或失败后）显示日志。
- 启动后默认打开浏览器 → 默认关；勾选「启动时打开界面」或按「打开界面」。
- 面板进程托管 DSH 生命周期 → 面板只负责展示与派发 CLI。
- 全平台完美「已打开则仅虚焦并刷新」→ 尽力而为。

## 结构（解耦）

状态全在 `$DSH_HOME/rebooter/` 的文件里（`job.json` / `job.log` / `panel.json`）。  
面板是本机 HTTP（`webPort + 10001`）+ 极简 HTML。  
真正干活的仍是现有 `performAction` / supervisor。  
只有窗口壳与桌面快捷方式按系统生成，落在 `package/panel/`，桌面快捷方式名称为 **DSH Server**。

## 按钮（稳定态）

| 状态 | 按钮 |
| --- | --- |
| 未启动 | 启动 · 更新 · 更新并启动 |
| 已启动 | 关闭 · 重启 · 更新并关闭 · 更新并重启 · 打开界面 |

忙碌时（`job.state === busy`）隐藏全部操作按钮，只留状态条 + 日志。  
侧栏菜单仍只有四项（DSH 已在跑）；从侧栏触发时也会自动唤起面板看进度。

## 进度与日志

- 始终有状态条（文案 + 忙碌时转圈）。
- 日志只在忙碌时出现；失败后保留到下一次空闲操作；成功空闲则收起。
- 关掉再开面板，进度与日志从文件恢复，无需手动刷新。

## 打开界面

「打开界面」→ 系统默认的打开方式，或已绑定的程序。点齿轮后在下方输入路径，或用「浏览」弹出系统文件选择器。确定后齿轮变为「清除」。勾选「启动时打开界面」写入 `panel.json`。启动类动作默认不打开界面。窗口高度随内容变化，空闲时不预留日志空白。

## 生成入口

`dsh-rebooter desktop` 与 Host 挂载时写入。入口在已安装插件的 `panel/` 里，用自身位置找到 `lib/cli.cjs`，不写死本机路径。桌面入口名为 **DSH Server**：Windows 快捷方式图标是 `dsh-server.ico`，Linux 用 `dsh-server.png`，macOS 是 `.app`（不留终端）。窗口组件起不来时，同一页面改由系统默认方式打开。文案只有 `zh` / `en` 两套，跟界面语言走。写快捷方式的临时文件不放在桌面。窗口宿主装在插件自己的 `node_modules` 里，需要 `Node 24`。换机器执行构建即可。
